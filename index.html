01PhotoMindLOCAL-FIRST / DESKTOPOpen-source desktop application · macOS + Windows+

A local-first photo culling and selection app for macOS and Windows. Find duplicates, compare visually similar shots, review possible same-person groups, and move unwanted images to a recoverable Bin. Processing stays on the device.

  • SHA-256 finds exact duplicates; visual matching and moment grouping help organise a library.
  • Local quality analysis and possible same-person groups support review; people groups are suggestions, not verified identities.
  • React and TypeScript sit on a Rust/Tauri backend with local SQLite storage. No LLM or remote service is used.

Rust · Tauri 2 · React · TypeScript · SQLite / SQLx

03ARKIVEENCRYPTION / WEB3Public testnet prototype · Base Sepolia+

An experimental encrypted personal vault and archival system. Files are encrypted in the browser, stored on Arweave, and indexed on Base. The current beta is a testnet prototype, not production-ready.

  • AES-256-GCM encrypts each file with a random key, wrapped for an authorised wallet and optional recovery passphrase or backup wallets.
  • Encrypted bundles live on Arweave; Base holds discovery and ownership references rather than the private file.
  • An offline .arkive copy and a public recovery specification support recovery independently of the website. Keep original files and an independent backup during the beta.

04ScintillaACCESSIBILITY / MAP CUESScintilla + CueLock · Research instrument+

Scintilla explores accessible navigation. Its live site now features CueLock, a semantic verifier for navigation cues on web maps: check whether routes and markers remain distinguishable under colour-vision differences.

  • Draw routes, place markers, or import GeoJSON on a real OpenStreetMap map; a schematic fallback is available.
  • Check named roles such as main route, backup, hazard, and destination under simulated colour-vision modes.
  • Suggest dual encodings, re-verify changes, and export review reports. A research instrument, not WCAG certification.

Web maps · GeoJSON · Colour-vision simulation · Semantic cue verification

        02 / RESEARCH & PhD

        Useful software.
        Questions worth testing.

        I’m interested in how people understand and control privacy in local-first tools, and how accessible visual cues support navigation. These proposed research interests grow from building PhotoMind, ARKIVE, and Scintilla/CueLock. I’m exploring PhD opportunities that connect human-computer interaction, privacy, and accessibility.

        01 / LOCAL-FIRST PRIVACY

        Can people tell where their data goes?

        How do interface explanations affect understanding of on-device processing, encrypted storage, and recovery? PhotoMind and ARKIVE offer concrete contexts for exploring this question.

        02 / ACCESSIBLE MAP CUES

        When colour stops carrying meaning, what works?

        Which combinations of colour, shape, line style, and labels help people distinguish routes and hazards under colour-vision differences?

        03 / TRUST & RECOVERY

        How can irreversible actions become understandable?

        How should photo cleanup and encrypted-vault recovery communicate consequences, uncertainty, and the options available before users commit?

        SCINTILLA / CUELOCK — PROJECT RESEARCH NOTE

        Checking meaning in map cues

        Problem: distinct route roles can become ambiguous when colour differences collapse.

        Approach: CueLock assigns semantic roles, simulates colour-vision differences, checks encodings, and suggests additional visual cues. Its documented method references Machado et al. (2009), CIEDE2000, and a dual-encoding rule.

        Related work: the project documentation places it alongside Color Oracle, Sim Daltonism, TextureMap, and Map Colouriser. Its focus is checking role distinctions and re-verifying changes.

        Evaluation and limitations: this is a working research instrument. No completed participant study or peer-reviewed evaluation is claimed here. Simulation and automated checks do not establish real-world accessibility or WCAG certification.

        Proposed next step: compare cue encodings in a task-based user study, measuring role recognition, errors, and confidence.
